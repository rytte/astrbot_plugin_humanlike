# 拟人化行为

AstrBot 插件，仓库目录名为 `astrbot_plugin_humanlike`。第一项功能是由模型管理的用户黑名单。

## 黑名单

- 模型可以拉黑用户、解除拉黑、查询名单，无需使用聊天指令。
- 拉黑范围是**当前机器人平台实例的全部群聊和私聊**，不同平台实例互不影响。
- 命中新消息后静默结束，不回复“你已被拉黑”，不进入唤醒、媒体预处理、会话等待、插件处理和模型调用。
- 所有已加载 AstrBot 配置中的管理员均受保护，机器人自身也不能被拉黑。用户后来被设为管理员时，已有黑名单记录立即失效；解除管理员身份后该记录会重新生效，可用解除工具删除记录。
- 名单由 AstrBot 插件 KV 存储持久保存，重启、重载和普通插件更新不会丢失。
- 停用插件或在配置文件／会话中禁用此插件时，不拦截对应消息；重新启用后继续使用原名单。

这是机器人的交互行为，不是 QQ 等平台的账号拉黑、删除好友、群禁言或踢人。

## 模型工具

工具名：`humanlike_blacklist`。

| 参数 | 含义 |
| --- | --- |
| `action` | `block` 拉黑、`unblock` 解除、`list` 查询当前平台名单 |
| `user_id` | 真实平台用户 ID，默认当前消息发送者；不要传昵称或原始 @ 文本 |
| `reason` | 可选拉黑原因，仅在新增记录时保存 |

调用示例：

```json
{"action": "block", "user_id": "123456789", "reason": "持续骚扰"}
```

```json
{"action": "unblock", "user_id": "123456789"}
```

```json
{"action": "list"}
```

工具返回 JSON，`ok` 表示是否成功，`changed` 表示是否新增或移除了记录。重复拉黑／解除不会重复写入。查询结果包含用户 ID、原因、UTC 创建时间与 `active` 状态。

工具供模型根据人设和互动情况调用，插件不额外限定只有管理员发起的会话才能使用。管理员保护在代码中强制执行，不依赖提示词。若需要限制工具的调用者，可使用 AstrBot 自带的工具权限设置。

可在人格提示词中加入：

> 遇到持续骚扰时，可以使用 humanlike_blacklist 决定是否拉黑；需要恢复互动时使用 unblock。使用真实用户 ID，不猜测身份。管理员不能被拉黑。

用户被拉黑后，其新消息不会进入模型，因此不能通过给机器人发消息自行解除；可由管理员或其他正常会话中的模型解除。拉黑针对生效后的新消息，已开始的回复、已经保存的历史及其他插件直接使用平台接口产生的行为不在此功能范围内。

## 安装

将本目录放入 AstrBot 的 `data/plugins/astrbot_plugin_humanlike`，在插件页面加载／重载，确认插件已启用，并让当前人格允许使用 `humanlike_blacklist` 工具。无需安装额外运行依赖。

`metadata.yaml` 中暂未填写真实作者和远程仓库地址；发布前请补充。作者会参与 AstrBot 的 KV 存储命名，正式使用后不要随意更改作者或插件名。

## 入口拦截与兼容性

本插件针对本地 AstrBot **4.29.3** 实现，版本范围暂限定为 `>=4.29.3,<4.30`。

该版本没有对插件开放“第一阶段之前”的消息钩子；普通高优先级监听器仍晚于媒体预处理，无法满足入口忽略。因此插件在加载时为 `PipelineScheduler._process_stages` 安装一个可撤销的入口检查，只在最外层处理时执行。命中后不进入任何阶段，原有执行上下文、追踪与平台结束帧仍由 AstrBot 自己处理。没有修改 AstrBot 源文件。

卸载／停用时恢复入口；若其他插件后来也包装了同一方法，则将本插件检查停用，避免覆盖其他插件的包装。升级 AstrBot 大版本或次版本前，应重新验证这一内部接口。

AstrBot 在进入管道前记录的接收日志仍会保留，黑名单不是消息擦除功能。

## 开发与验证

在包含 AstrBot 运行依赖的 Python 环境中执行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
ruff check .
ruff format --check .
```

测试默认使用同级 `../AstrBot` 源码，也可通过 `ASTRBOT_SOURCE` 环境变量指定其他源码目录。
